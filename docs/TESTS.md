# Статистические критерии, оптимальный набор и методы оптимизации

Обозначения: n — длина последовательности, ε = ε₁…εₙ — биты, Xᵢ = 2εᵢ − 1 ∈ {−1, +1},
α — уровень значимости (по умолчанию 0.01), Q(a, x) — регуляризованная верхняя неполная
гамма-функция (`igamc` в NIST STS), erfc — дополнительная функция ошибок.

## 1. Батареи

### 1.1. NIST SP 800-22 rev.1a (15 тестов)

| # | Тест | Статистика, распределение | Мин. n | Что обнаруживает |
|---|---|---|---|---|
| 1 | Частотный | S = \|ΣXᵢ\|/√n, p = erfc(S/√2) | 100 | смещение |
| 2 | Частотный в блоках (M=128) | χ² = 4M Σ(πᵢ − ½)², p = Q(N/2, χ²/2) | 100 | локальное смещение |
| 3 | Серии | V = число серий, нормальное приближение | 100 | слишком частое/редкое чередование |
| 4 | Длиннейшая серия единиц | χ² по категориям длины, M = 8/128/10⁴ | 128 | «залипание» |
| 5 | Ранги матриц 32×32 | χ² по рангам 32, 31, ≤30 над GF(2) | 38 912 | линейная зависимость |
| 6 | Спектральный (ДПФ) | число пиков \|ДПФ\| < √(n ln 20) | 1 000 | периодичность |
| 7 | Неперекрывающиеся шаблоны (m=9) | 148 шаблонов, χ² по N=8 блокам | 4 096 | избыток/недостаток паттернов |
| 8 | Перекрывающиеся шаблоны (m=9) | χ² по числу вхождений 1…1 в блоках 1032 бит | 51 600 | длинные серии единиц |
| 9 | Универсальный Маурера | среднее log₂ расстояния между повторами L-блоков | 8 080 | сжимаемость |
| 10 | Линейная сложность (M=500) | χ² по отклонению сложности Берлекэмпа–Мэсси | 100 000 | РСЛОС |
| 11 | Последовательный (m=16) | ∇ψ²ₘ, ∇²ψ²ₘ (2 p-значения) | 64 | неравномерность m-грамм |
| 12 | Приближённая энтропия (m=10) | 2n(ln 2 − ApEn) ~ χ² | 64 | регулярность |
| 13 | Кумулятивные суммы | max\|Sₖ\| вперёд и назад (2 p) | 100 | дрейф среднего |
| 14 | Случайные отклонения | визиты в x∈{±1…±4} по циклам (8 p) | 10⁶ | структура блуждания |
| 15 | Случайные отклонения (вариант) | визиты в x∈{±1…±9} (18 p) | 10⁶ | структура блуждания |

Параметры по умолчанию — рекомендованные стандартом; при недостаточной длине m для
serial/ApEn и L для теста Маурера уменьшаются автоматически по условиям применимости NIST.

### 1.2. DieHard (11 тестов)

Классический DieHard работает с 32-битными словами и рассчитан на файл около 80 Мбит.
Здесь число повторений подстраивается под длину входа (с нижней границей).

| Тест | Суть | Распределение |
|---|---|---|
| Birthday spacings | 512 «дней рождения» среди 2²⁴ дней (старшие и младшие 24 бита) | Пуассон(λ=2), χ² |
| Ранги 32×32, 31×31, 6×8 | ранги матриц из слов / байтов слов | точные вероятности рангов, χ² |
| Bitstream | пропущенные 20-битные слова в 2²¹ битах | N(141909, 428) |
| Count-the-1s (stream) | байты → буквы A…E по числу единиц; 5-буквенные слова | Q5 − Q4 ~ χ²(2500) |
| Parking lot | 12 000 попыток парковки на площадке 100×100 | N(3523, 21.9) |
| Minimum distance | 8000 точек; квадрат мин. расстояния | Exp(0.995), KS |
| 3D spheres | 4000 точек в кубе; куб мин. расстояния | Exp(30), KS |
| Craps | 200 000 партий: число выигрышей и длины партий | Bin(·, 244/495); χ² |
| Runs up/down | серии возрастания/убывания (статистика Кнута) | χ²(6) |

Не включены тесты, требующие десятков мегабит при любом числе повторений
(OPSO/OQSO/DNA, OPERM5, Squeeze, Overlapping sums). Для полной сверки предусмотрен
адаптер к утилите `dieharder` (`rngtest/verify.py`).

### 1.3. TestU01 SmallCrush (адаптация, 10 тестов)

BirthdaySpacings (t=2), Collision, Gap, SimpPoker, CouponCollector, MaxOft,
WeightDistrib, MatrixRank (60×60), HammingIndep, RandomWalk1. Числа U ∈ [0,1)
получаются из 32-битных слов; распределения статистик точные (числа Стирлинга,
биномиальное, принцип отражения), категории с ожидаемой частотой < 5 объединяются.

### 1.4. FIPS 140-2 (4 теста на 20 000 бит)

Монобитный (9725 < X < 10275), покер (2.16 < X < 46.17), серий (интервалы для длин
1…6+), длинной серии (нет серий ≥ 26). Решение — по границам стандарта; p-значения
приводятся справочно. Исторически использовались для самопроверки криптомодулей при
включении, поэтому подходят для IoT.

### 1.5. Базовые тесты Menezes (HAC, гл. 5.4.4)

Частотный, двухбитовый (serial), покер, серий (блоки и пропуски) и
**автокорреляционный**: A(d) = Σ εᵢ ⊕ εᵢ₊d, Z = 2(A(d) − (n−d)/2)/√(n−d) ~ N(0,1),
проверяются сдвиги d ∈ {1,…,8, 16, 32}.

## 2. Калибровка: ложные отказы

Каждый тест прогнан на 200 независимых последовательностях PCG64 по 10⁶ бит. Доля
отказов при α = 0.01 лежит в диапазоне 0–3 % (ожидается 1 % ± 1.4 % при 200 испытаниях),
при α = 0.05 — 2–9 %; p-значения проходят KS-проверку на равномерность (кроме
случайных отклонений NIST, где p-значения для разных состояний в одной
последовательности коррелированы, и FIPS, где статистики дискретны).

## 3. Оптимальный набор

### 3.1. Постановка

Набор оптимален, если он:

1. **необходим** — каждый тест обнаруживает класс дефектов, который не обнаруживают
   остальные (или обнаруживает его заметно дешевле);
2. **достаточен** — вместе тесты покрывают все рассматриваемые классы дефектов;
3. **экономен** — минимальная суммарная трудоёмкость и память;
4. **не избыточно строг** — вероятность ложной отбраковки хорошей последовательности
   растёт с числом проверок: 1 − (1 − α)^T. Для полной NIST (188 p-значений) при α = 0.01
   это ≈ 85 % без поправок. Это и есть упомянутая в ТЗ «излишняя строгость».

### 3.2. Эксперимент (`python -m rngtest optimize`, страница «Оптимальный набор»)

14 сценариев дефектов (`rngtest/optimize.py`): смещение p = 0.505 и 0.51; марковская
корреляция 0.505 и 0.51; периодичность 2¹² и 2¹⁷; РСЛОС степени 31; Xorshift32; RANDU;
младшие биты ЛКГ; залипший бит; дрейф ±1 % и ±3 %; счётчик. Для каждого теста
измеряются мощность (доля обнаружений, 6 повторов, n = 10⁶) и стоимость (мс/Мбит).
Жадный алгоритм взвешенного покрытия добавляет тест с максимальным
`прирост покрытия / стоимость^w`.

Основные наблюдения (Apple M-series, C-ускоритель включён):

* **Xorshift32 обнаруживают только ранговые тесты** (NIST rank, DieHard 32×32/31×31):
  генератор линеен над GF(2), но идеально сбалансирован.
* **РСЛОС** обнаруживают линейная сложность (мощность 1.0) и ранги. Линейная сложность —
  единственный тест, который ловит РСЛОС степени от 33 до M/2 = 250.
* **Смещение** надёжнее всего ловят частотный тест и кумулятивные суммы (они
  дублируют друг друга: мощности совпадают на всех сценариях).
* **Корреляцию соседних бит** ловят серии, автокорреляция, HAC serial/poker/runs;
  частотный тест её не видит.
* **Периодичность** с длинным периодом (2¹⁷) — ДПФ, шаблоны, birthday spacings.
* **Дрейф ±1 %** — самый трудный сценарий: лучше всего его видят HammingIndep и
  частотный тест в блоках.
* Дорогие тесты (serial m=16 — 31 мс/Мбит, parking lot — 85 мс/Мбит, Маурер — 14 мс/Мбит)
  не обнаруживают ничего, что не обнаруживали бы дешёвые.

### 3.3. Итоговый набор (регламентный режим, `--battery optimal`)

| Тест | Закрываемый класс дефектов | Трудоёмкость |
|---|---|---|
| Частотный | смещение | O(n) |
| Частотный в блоках | локальное смещение, дрейф | O(n) |
| Серии | корреляция соседних бит | O(n) |
| Автокорреляция (d = 1…32) | корреляции на сдвигах (требование ТЗ) | O(n·k), C: XOR+popcount |
| Длиннейшая серия единиц | залипание, короткий период младших бит | O(n) |
| HammingIndep | зависимость весов соседних слов, дрейф | O(n) |
| Спектральный (ДПФ) | периодичность | O(n log n) |
| Ранги 32×32 | линейность над GF(2) | O(n·32) |
| Линейная сложность | РСЛОС | O(n·M), C-ядро |

Измеренная вероятность обнаружения при n = 10⁶: **100 % для 13 из 14 сценариев**;
слабый дрейф ±1 % — 31 % (это предел различимости на 10⁶ битах: полная NIST его тоже
обнаруживает не всегда). Набор состоит из 9 тестов (18 p-значений вместо 188 у полной
NIST) и стоит около 40 мс на 1 Мбит.

**IoT-набор** (`--battery iot`, динамический контроль): те же тесты без ДПФ и
линейной сложности. Все тесты O(n), память невелика. На 14 сценариях покрытие то же,
что у оптимального набора, при стоимости около 9 мс/Мбит; линейная сложность выше 32
им не проверяется. Минимальное окно — 320 000 бит (на более коротких окнах HammingIndep
пропускается автоматически).

## 4. Методы оптимизации

| Метод | Где | Эффект (n = 10⁶) |
|---|---|---|
| Векторизация NumPy вместо циклов Python | все тесты | частотный: 21 мс → 0.15 мс (×140); серии: 72 мс → 0.05 мс (×1400) |
| Векторизация «поперёк блоков» (Берлекэмп–Мэсси сразу для всех блоков) | `berlekamp_massey_batch` | 28 с → 1.2 с (×23) |
| Нативное C-ядро (`-O3`, автовекторизация NEON/AVX) | `native/fastrng.c` | линейная сложность: 1.2 с → 25 мс (×48 к NumPy, ×1100 к Python) |
| Упакованные биты (8 бит/байт) + аппаратный popcount | частотный, автокорреляция | память ×8 меньше; popcount ≈ 0.004 мс |
| XOR сдвинутых байтов вместо побитового сравнения | автокорреляция | ×4 к NumPy, память 1 КБ вместо 977 КБ |
| Строки матриц = машинные слова (`packbits().view('>u4')`) | ранговые тесты | память 16 МБ → 1.1 МБ |
| Метод Гаусса над GF(2), векторизованный по матрицам | ранги NIST/DieHard/TestU01 | цикл только по 32 столбцам вместо 32·32·N операций |
| Подсчёт всех 148 шаблонов одной гистограммой (`bincount`) | неперекрывающиеся шаблоны | 148 проходов → 8 |
| Поиск предыдущего вхождения сортировкой | тест Маурера | без цикла Python по 10⁵ блокам |

Цифры воспроизводятся командой `python -m rngtest bench` и на странице
«Производительность».

## 5. Верификация

**Эталон NIST** (`python -m rngtest verify`): на первых 10⁶ битах двоичной записи e
(как файл `data.e` из sts-2.1.2) совпали все 17 контрольных p-значений из
Приложения B SP 800-22 с точностью до 10⁻⁶. Две тонкости, найденные при сверке:

* файл `data.e` начинается с целой части «10», а не с дробной части e;
* для теста перекрывающихся шаблонов значение 0.110434 в Приложении B посчитано по
  старым, неточным вероятностям π₀…π₅ — они доступны как `legacy=True`, по умолчанию
  используются исправленные значения из sts-2.1.2; в тесте линейной сложности
  π₀ = 0.01047, как в эталонном коде.

**DieHard:** при установленной утилите `dieharder` (Linux: `sudo apt install dieharder`)
страница «Верификация» и `rngtest verify` запускают на одной и той же
последовательности обе реализации и сравнивают решения.

**Функциональная проверка (ТЗ п. 6.5.1):** все тесты проходят на эталонной последовательности PCG64 с фиксированным seed и
отвергают последовательность из одних нулей; результаты на чередовании 0101… и
счётчике выводятся справочно.
