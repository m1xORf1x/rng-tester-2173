# rngtest — оценка выходных последовательностей датчиков случайных чисел

Учебный проект 2173 (МИЭМ НИУ ВШЭ). Программный комплекс проверяет двоичные
последовательности на случайность батареями статистических тестов, позволяет
собрать свою батарею, содержит обоснованный «оптимальный» набор тестов и выводит
метрики: p-значения, статистики, время, пиковую память, скорость обработки.

| Что есть | Где |
|---|---|
| NIST SP 800-22 — все 15 тестов, **сверены с эталоном стандарта (17/17 значений)** | `rngtest/tests_nist.py` |
| DieHard — 11 тестов | `rngtest/tests_diehard.py` |
| TestU01 SmallCrush — 10 тестов (адаптация) | `rngtest/tests_testu01.py` |
| FIPS 140-2 (4 теста) и базовые тесты Menezes/HAC, включая автокорреляцию | `rngtest/tests_extra.py` |
| Оптимальный набор (9 тестов) и облегчённый IoT-набор (7 тестов) | `rngtest/runner.py` |
| Пользовательская батарея — любые тесты с любыми параметрами | GUI / `--tests` |
| Экспериментальный подбор оптимального набора | `rngtest/optimize.py` |
| Верификация (эталон NIST, адаптер dieharder, функциональная проверка) | `rngtest/verify.py` |
| C-ускоритель (popcount, XOR на упакованных битах, Берлекэмп–Мэсси) | `rngtest/native/` |
| CLI, динамический (потоковый) режим, отчёты JSON / CSV / TXT | `rngtest/cli.py`, `rngtest/report.py` |
| Графический интерфейс | `app.py` |

Подробнее: [описание тестов и обоснование набора](docs/TESTS.md) ·
[документация разработчика](docs/DEVELOPER.md).

## 1. Установка

Нужен Python 3.9+ и (необязательно) компилятор C — `cc`/`gcc`/`clang`.

```bash
cd rng_tester
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

C-ускоритель собирается автоматически при первом запуске. Если компилятора нет,
всё работает на NumPy (медленнее только тест линейной сложности). Отключить
ускоритель: `RNGTEST_NO_NATIVE=1`.

## 2. Графический интерфейс

```bash
streamlit run app.py
```

Откроется страница в браузере (http://localhost:8501). Две вкладки:

* **Набор тестов** — все тесты, сгруппированные по батареям; галочками собирается
  пользовательский набор. Кнопка «Рекомендуемый набор» отмечает оптимальные 9 тестов.
* **Запуск** — выбор данных (генератор / файл / ручной ввод) и α. По кнопке
  «Запустить» последовательность проверяется всеми пятью стандартными батареями
  (NIST, DieHard, TestU01, FIPS 140-2, HAC) и пользовательским набором. Ниже выводятся
  сводная таблица (пройдено, вердикт, время, скорость, пик памяти), графики времени и
  памяти по батареям, подробные результаты каждого теста и выгрузка отчёта.

Верификация, подбор оптимального набора и замеры производительности доступны
из командной строки (`verify`, `optimize`, `bench`).

## 3. Командная строка

```bash
python -m rngtest list                                    # батареи и тесты
python -m rngtest run data.bin --battery nist             # файл, батарея NIST
python -m rngtest run data.txt --format ascii -b optimal -o report.json -o report.csv
python -m rngtest run -g urandom -n 1000000 -b diehard    # встроенный генератор
python -m rngtest run data.bin --tests nist.frequency,nist.runs,hac.autocorrelation --alpha 0.05
python -m rngtest run data.bin -b nist -m 100             # 100 подпоследовательностей + анализ 2-го уровня
python -m rngtest run data.bin -b nist --param nist.serial.m=8 --param nist.block_frequency.M=256
python -m rngtest verify --functional                     # верификация
python -m rngtest optimize --reps 5                       # подбор оптимального набора
python -m rngtest bench                                   # замеры производительности
python -m rngtest generate lfsr lfsr.bin -n 1000000       # записать тестовую последовательность
```

Код возврата `run`: 0 — гипотеза о случайности не отвергнута, 1 — отвергнута
(удобно для скриптов и CI).

**Динамический режим** (ТЗ п. 5.1) — поток режется на окна, каждое тестируется сразу:

```bash
cat /dev/hwrng | python -m rngtest stream --window 1000000 --battery iot
head -c 12500000 /dev/urandom | python -m rngtest stream -w 1000000
```

```
окно     0: OK   7/7   136.4 Мбит/с
окно     1: ТРЕВОГА  3/7    74.2 Мбит/с  nist.runs,nist.longest_run,nist.rank
```

## 4. Форматы данных

**Вход:**

| Формат | Описание |
|---|---|
| `bin` | сырые байты; каждый байт — 8 бит, старший бит первым (как у `/dev/urandom`, dieharder `-g 201`) |
| `ascii` | текст из символов `0` и `1`; пробелы и переводы строк игнорируются (как `data.e` в NIST STS) |
| `hex` | шестнадцатеричный текст |
| `auto` | `ascii`, если файл состоит только из 0/1/пробелов, иначе `bin` |

**Выход:** JSON (полный отчёт со всеми p-значениями и деталями), CSV (по строке на
тест), TXT (читаемый отчёт). Поля на тест: `status` (pass / fail / skipped / error),
`p_value` (итоговое), `p_values` (все), `statistic`, `time_s`, `peak_mem_bytes`,
`throughput_mbit_s`, `params`, `details`.

## 5. Как читать результат

* Для каждого теста проверяется H₀ «последовательность случайна». Если p < α — тест
  не пройден.
* Если у теста несколько p-значений (шаблоны — 148, случайные отклонения — 8 и т.д.),
  итоговое p = 1 − (1 − p_min)^k (поправка Шидака), чтобы решение принималось ровно
  на уровне α.
* Даже идеальный генератор в среднем не проходит долю α тестов. Поэтому вердикт по
  батарее: последовательность отвергается, если хотя бы один тест дал
  p < 1 − (1 − α)^(1/T) ≈ α/T (поправка Шидака), или нарушены границы FIPS 140-2, или число отказов неправдоподобно
  велико для Bin(T, α). При разбиении на подпоследовательности применяется анализ
  второго уровня NIST (доля прошедших + равномерность p-значений).
* Тест помечается «пропущен», если последовательность короче минимально допустимой
  (например, случайные отклонения NIST требуют 10⁶ бит и ≥ 500 циклов).

## 6. Пример из Python

```python
from rngtest import run_battery, generate, load_file

bits = load_file("data.bin")                     # или generate("urandom", 1_000_000)
rep = run_battery("optimal", bits, alpha=0.01)
print(rep.verdict, rep.total_time_s, rep.peak_mem_bytes)
for r in rep.results:
    print(r.name, r.status, r.p_value, r.throughput_mbit_s)
```
